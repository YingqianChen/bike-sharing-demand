# Bike Sharing Demand Prediction

Hourly bike-share demand forecasting for Washington D.C.'s Capital Bikeshare
system (Kaggle "Bike Sharing Demand", 2011–2012). Four models are benchmarked —
Linear Regression, Random Forest, a PyTorch ANN, and a **Bidirectional LSTM** —
with the BiLSTM achieving the best validation performance.

| Model | RMSE ↓ | MAE ↓ | R² ↑ | MAPE ↓ |
|---|---|---|---|---|
| **BiLSTM** | **85.03** | **54.42** | **0.847** | **25.8%** |
| ANN | 100.28 | 67.05 | 0.788 | 27.8% |
| Random Forest | 105.25 | 72.09 | 0.766 | 29.7% |
| Linear Regression | 105.94 | 70.59 | 0.763 | 29.3% |

## Highlights

- **Leakage-free pipeline**: windspeed imputation and temporal target-encoded
  (TTE) features are computed from training data only; every split is
  chronological.
- **Regularized BiLSTM**: bidirectional, 2 layers, gradient clipping, LayerNorm,
  weight decay, ReduceLROnPlateau and early stopping. An ablation showed that
  attention pooling did *not* help (`use_attention=False` won).
- **Interpretability**: SHAP ranks the TTE features above raw weather/time
  features — they account for 63.2% of total |SHAP|.

## Repository structure

| File | Description |
|---|---|
| `Bike_Demand_Analysis.ipynb` | End-to-end pipeline: EDA → imputation → feature engineering → tuning → model comparison → SHAP → test submission. Fully executed (outputs embedded). |
| `train.csv` / `test.csv` | Inputs read by the notebook (same directory). |
| `sampleSubmission.csv` | Kaggle submission-format template. |
| `model_metrics.csv` | Validation metrics for all four models. |
| `lstm_tuning_results.json` | BiLSTM hyperparameter search results. |
| `final_submission.csv` | Test-set predictions generated by the best model. |
| `best_model_validation_predictions.csv` | Actual vs. predicted on the validation holdout. |

## Running it

```bash
pip install -r requirements.txt
jupyter notebook Bike_Demand_Analysis.ipynb
```

Run the cells top to bottom. The notebook reads `train.csv` / `test.csv` from
its own directory.
